# precision-recall-f1-threshold-analysis

## Summary

Evaluates how well differential-abundance tool calls discriminate between sample groups by converting significant-ASV calls into per-ASV AUROC, precision, recall, and F1 at fixed AUC thresholds (0.7 and 0.9), separately for relative-abundance and CLR-transformed inputs.

## When to use

Use when significant-ASV result tables from DA tools (ALDEx2, ANCOM-II, LEfSe, edgeR, DESeq2, etc.) on grouped 16S datasets are available and tool discrimination performance must be quantified and compared across input types.

## When NOT to use

- The goal is to run the DA tools themselves (significant-ASV calling) rather than evaluate their discrimination output; use run_all_tools.sh instead.
- The metadata contains more than two sample groupings; the pipeline metadata format supports a maximum of 2 groupings.
- Only unfiltered datasets are under analysis and no false-positive tables from run_all_FP_datasets_filt.sh are available as the reference.

## Inputs

- Significant-ASV result tables from each DA tool on the 38 filtered datasets (output of run_0.1_filt_datasets.sh)
- False-positive analysis tables for the filtered datasets (output of run_all_FP_datasets_filt.sh)
- ASV abundance tables in relative-abundance and CLR-transformed form
- Two-column TSV metadata (sample IDs and group labels, maximum 2 groupings)

## Outputs

- Summary TSV of per-tool mean AUROC, precision, recall, and F1 for both relative-abundance and CLR input types
- Per-ASV ROC curve plots (ggplot2, Supplementary Figs. 3-4 layout)
- Per-tool metric summaries (bar/summary plots at AUC thresholds 0.7 and 0.9)

## How to apply

Load the significant-ASV tables produced by each DA tool on the 38 filtered datasets (generated by run_0.1_filt_datasets.sh) together with the false-positive analysis tables from run_all_FP_datasets_filt.sh in R. For each tool, treat its significant-ASV calls as prediction scores and compute per-ASV ROC curves and AUC values with ROCR, running the computation separately on relative-abundance and CLR-transformed abundance inputs, then aggregate per-ASV AUCs into a per-tool mean AUROC for each input type. Binarize tool performance at AUC thresholds of 0.7 and 0.9 and compute precision, recall, and F1 per tool per input type. Plot the ROC curves and per-tool metric summaries with ggplot2 to reproduce the Supplementary Figs. 3-4 layout. The rationale is that discrimination metrics separate tools that call many false positives (low precision, e.g. LEfSe, edgeR) from conservative tools with few false positives but lower recall (ANCOM-II, ALDEx2).

## Examples

```
library(ROCR); pred <- prediction(sig_scores, labels); auc <- performance(pred, measure = "auc")@y.values[[1]]
```

## Evaluation signals

- The summary TSV exists and contains an entry for every DA tool under both input types (relative abundance and CLR).
- Computed mean AUROC, precision, recall, and F1 match the Supplementary Fig. 3-4 values: ANCOM-II precision 0.99 and ALDEx2 precision 0.82 at threshold 0.7 on relative abundance.
- Wilcoxon on CLR data reaches an F1 of 0.70.
- At threshold 0.7, ANCOM-II and ALDEx2 show the highest precision (medians 1.0 and 0.83 on CLR data) with lower recall than LEfSe and edgeR.
- Per-ASV AUC values fall within [0, 1] and each tool's mean AUROC is reproducible when the computation is re-run per input type.

## Limitations

- The randomized approach for estimating FDR is not a perfect representation of real data, so few significant ASVs under this approach is not proof of low practical FDR.
- No direct simple recommendation of a specific tool can be made from the analysis; precision/recall trade-offs differ by tool and input type.
- Recall is lower for conservative tools (ANCOM-II, ALDEx2), so high precision alone does not imply superior overall performance.
