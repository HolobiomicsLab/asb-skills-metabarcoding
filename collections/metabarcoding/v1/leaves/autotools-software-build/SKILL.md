# autotools-software-build

## Summary

Build a scientific tool such as MAPseq from its GitHub source using the GNU autotools toolchain (bootstrap, configure, make, make install), installing the binary together with its data files so reference databases resolve correctly.

## When to use

Use when a tool like MAPseq must be installed from a cloned GitHub repository rather than a binary release, and the project ships a 'configure' script or 'bootstrap' requiring autoconf, GNU make, libtool, and related build dependencies.

## When NOT to use

- A prebuilt binary package (e.g. mapseq-1.2-linux.tar.gz or mapseq-1.2-macosx.tar.gz from the GitHub Releases page) is available and sufficient — unpacking avoids the whole build step.
- The user only needs to run an already-installed tool (e.g. 'mapseq rawseqs.fa > rawseqs.fa.mseq'); no compilation is required.

## Inputs

- cloned GitHub source repository (e.g. jfmrod/MAPseq)
- build toolchain: build-essential, autoconf/autotools, GNU make, libtool, libncurses5-dev, svn, wget, git

## Outputs

- compiled and installed executable (e.g. $HOME/usr/bin/mapseq or system-wide /usr/local install)
- reference data files downloaded by setup.sh placed relative to the binary
- working 'configure' script generated by bootstrap from configure.ac

## How to apply

Clone the repository (e.g. 'git clone https://github.com/jfmrod/MAPseq.git') and install prerequisites such as build-essential, wget, subversion, git, libncurses5-dev, and libtool. For a cloned (non-release) checkout, run './setup.sh' to download eutils and reference data files, then './bootstrap' to regenerate the configure script with autoconf/autotools. Run './configure' (optionally with a prefix such as '--prefix=$HOME/usr' to install into the home directory, or CC='gcc -arch ...' for multi-architecture builds), then 'make', optionally 'make check' for self-tests, and 'make install'. Keep the binary inside its directory: MAPseq searches for its reference data files relative to the binary's path, so moving only the binary breaks the installation; validate by running the tool on a FASTA input and checking that .mseq classifications are produced.

## Related tools

- **MAPseq** (Target software being compiled and installed from source via the autotools toolchain) — https://github.com/jfmrod/mapseq
- **autoconf** (Creates the 'configure' script from 'configure.ac' during the bootstrap step)
- **GNU make** (Drives compilation ('make'), self-tests ('make check'), and installation ('make install'))

## Examples

```
git clone https://github.com/jfmrod/MAPseq.git && cd MAPseq && ./setup.sh && ./bootstrap && ./configure --prefix=$HOME/usr && make && make install
```

## Evaluation signals

- './configure' completes without errors and generates a Makefile honoring any --prefix setting.
- 'make check' (optional self-tests) passes before 'make install'.
- The installed binary is found at the expected prefix path (e.g. $HOME/usr/bin/mapseq) and the reference data files remain alongside it, since data files are searched relative to the binary's path.
- Running the installed tool on a test FASTA (e.g. 'mapseq rawseqs.fa > rawseqs.fa.mseq') produces a valid .mseq classification output rather than a missing-reference error.

## Limitations

- Moving the MAPseq binary alone breaks the installation because data files are searched for relative to the binary's path — the whole directory must be relocated.
- './bootstrap' is only needed when cloning the git repository; it requires autotools/autoconf packages, plus svn, wget, git, libncurses5-dev, and libtool as source-build dependencies.
- The article's extracted docs note no changelog beyond the README history; building an older checkout may require version-specific fixes (e.g. v1.2.2 fixed a multithreaded race condition).
