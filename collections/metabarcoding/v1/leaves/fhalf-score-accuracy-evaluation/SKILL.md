# fhalf-score-accuracy-evaluation

## Summary

Evaluate rRNA read classification accuracy using the F-half (F½) score against ground-truth assignments, the metric MAPseq's authors used to quantify accuracy trade-offs, including the cost of removing near-identical sequences from the reference database.

## When to use

Use when benchmarking rRNA taxonomy/OTU classifiers (e.g. MAPseq vs competing tools) against a known-identity read set, or when quantifying how reference redundancy reduction degrades mapping accuracy.

## When NOT to use

- Input is a plain abundance/OTU count table (e.g. a .mseq-derived otutable) with no read-level ground truth — no classification accuracy can be computed
- The goal is speed benchmarking only; the article reports MAPseq separately as up to one hundred times faster, a runtime metric distinct from F½ accuracy
- Reads have no known taxonomic identity, since the F½ score requires ground-truth assignments to score predictions

## Inputs

- Known-identity rRNA read benchmark set (amplicon and shotgun reads with ground-truth taxonomic assignments)
- Full-length rRNA reference database (e.g. the MAPseq standard reference with taxonomy and OTU cluster files)
- Optionally, reduced-redundancy reference databases generated by clustering and removing near-identical sequences at progressively lower redundancy levels
- MAPseq .mseq classification output files (simple or confidences format)

## Outputs

- F-half (F½) classification accuracy score per tool/condition
- Table of F½ accuracy versus reference redundancy level
- Comparison of accuracy degradation trends across MAPseq and competing tools

## How to apply

Assemble a benchmark set of amplicon and shotgun rRNA reads with ground-truth taxonomic assignments, plus a full-length rRNA reference database. For each condition under test (e.g. a series of reduced reference databases generated by clustering and removing near-identical sequences at progressively lower redundancy levels), build the MAPseq k-mer search index and classify all reads in a single MAPseq run. Compute the F-half score of predicted assignments versus ground truth, weighting precision over recall; the article benchmarks tools on this metric and reports MAPseq as up to 30% more accurate (F½ score) than existing solutions. Tabulate F½ accuracy versus each condition and check the degradation trend against the published behaviour (Fig. 1g-h and Supplementary Fig. S2). When choosing MAPseq confidence thresholds, apply the README's recommendation of a combined confidence cutoff of 0.4 or 0.5, which yielded the highest F1/2-score in their benchmarks.

## Related tools

- **MAPseq** (k-mer search classifier whose read assignments are scored with the F½ metric against ground truth) — https://github.com/jfmrod/mapseq
- **GNU make** (build step for compiling MAPseq from source prior to running the benchmark mappings)
- **autoconf** (generates the configure script used to build MAPseq for the benchmark environment)

## Examples

```
mapseq rawseqs.fa > rawseqs.fa.mseq
```

## Evaluation signals

- F½ score is computed on every read in the known-identity set, so the scored read count must equal the benchmark read count (no reads silently dropped)
- F½ accuracy at the full, unreduced reference database should match the tool's reported benchmark accuracy (MAPseq reported up to 30% higher F½ than competing solutions)
- Monotonically decreasing F½ accuracy as reference redundancy is progressively lowered; the degradation trend should correspond to Fig. 1g-h and Supplementary Fig. S2
- With the default MAPseq 'simple' output, assignments are emitted at combined confidence >= 0.5; re-running with the recommended 0.4 cutoff should not lower the achieved F½ score
- Classification output parses as valid .mseq: tab-separated fields with query id, reference id, alignment score, pairwise identity, and taxonomy/confidence fields

## Limitations

- F½ weighting favours precision over recall (F1/2), so a tool with many unclassified reads can score well; interpretation must account for classification coverage
- Accuracy depends on the combined confidence cutoff: the README recommends 0.4 or 0.5 as the value yielding the highest F1/2-score, and other cutoffs may shift results
- Reducing reference redundancy by removing near-identical sequences carries a significant trade-off cost in mapping accuracy for all methods tested, so results from reduced databases do not represent full-database performance
- MAPseq's default OTU taxonomy depends on precomputed high-quality OTU clusters of the reference set; custom references require properly formatted taxonomy files with identity cutoff headers
