# reference-sensitivity-benchmarking

## Summary

Quantifies how trimming near-identical sequences from a full-length rRNA reference database degrades read-classification accuracy (F½ score) for MAPseq and competing tools, exposing the redundancy-vs-accuracy trade-off (Fig. 1g-h, Supplementary Fig. S2).

## When to use

Use when deciding whether a full-length rRNA reference database can be made smaller by removing near-identical sequences, and you need to measure the resulting cost in mapping/classification accuracy against ground-truth assignments.

## When NOT to use

- The goal is general classification performance rather than sensitivity to reference database composition — use the paper's main benchmark with the full default reference instead.
- Reads lack ground-truth assignments; F½ accuracy against known identities cannot be computed, so the benchmark is not meaningful.
- The reference database is a marker set other than full-length rRNA sequences (e.g. protein or functional databases); the redundancy-reduction trade-off was established for rRNA references only.

## Inputs

- Full-length rRNA reference database (FASTA plus taxonomy file, e.g. MAPseq's mapref reference with NCBI and OTU taxonomies)
- Known-identity rRNA read benchmark set (amplicon and shotgun reads with ground-truth taxonomic assignments)
- Series of redundancy-reduced reference databases generated by clustering at progressively lower redundancy levels

## Outputs

- F½ classification accuracy per reference redundancy level
- Table of F½ accuracy versus reference redundancy level for MAPseq and competing tools
- Degradation trend comparable to Fig. 1g-h and Supplementary Fig. S2

## How to apply

Start from the full-length rRNA reference database used by MAPseq (e.g. the mapref reference shipped with v1.2.6) and a benchmark set of amplicon and shotgun rRNA reads whose true taxonomic identities are known. Generate a series of reduced reference databases by clustering and removing near-identical sequences at progressively lower redundancy levels, rebuilding the MAPseq k-mer search index for each level. For each redundancy level, classify the known-identity reads in a single MAPseq run (optionally also running competing classifiers on the same reduced references) and compute the F½ score against ground-truth assignments, using the combined confidence cutoff that the authors found optimal (0.4–0.5). Tabulate F½ accuracy versus redundancy level and check whether the degradation reproduces the trend in Fig. 1g-h and Supplementary Fig. S2 — the paper's finding is that reducing redundancy has a significant accuracy cost for all methods tested.

## Related tools

- **MAPseq** (k-mer search classifier whose reference index is rebuilt at each redundancy level to classify the known-identity benchmark reads) — https://github.com/jfmrod/mapseq
- **autoconf** (used to generate the configure script when building MAPseq from source for the benchmark)
- **GNU make** (compiles and installs MAPseq v1.2.6 via 'make' and 'make install' before benchmarking)

## Examples

```
./configure && make && make install; mapseq reads.fa <reducedref.fasta> <reducedref.tax> > reads.fa.mseq
```

## Evaluation signals

- F½ score is computed against ground-truth assignments for every redundancy level, with a monotonically decreasing trend expected as redundancy is reduced.
- The F½-versus-redundancy tabulation should reproduce the behaviour reported in Fig. 1g-h and Supplementary Fig. S2 of the MAPseq paper.
- The default (full) reference run should serve as the accuracy ceiling; reduced references must not exceed it.
- MAPseq combined confidence cutoff is fixed at 0.4–0.5 across all levels so that observed accuracy changes are attributable to reference redundancy, not threshold tuning.
- MAPseq should classify the entire benchmark read set in a single mapseq run per redundancy level, producing one .mseq output per level.

## Limitations

- Reducing reference dataset redundancy by removing near-identical sequences carries a significant trade-off cost in mapping accuracy for all methods tested, so a smaller reference cannot be assumed to be loss-free.
- MAPseq accuracy depends on the combined confidence cutoff; values outside the recommended 0.4–0.5 range lower the F½ score and could confound the redundancy comparison.
- MAPseq data files are searched relative to the binary's path — moving only the binary breaks the installation, which can invalidate benchmark runs if the installed tree is reorganized.
- Taxonomy files must follow MAPseq's two-column format with a '#cutoff:' header of per-level identity cutoffs; malformed custom reduced-reference taxonomy files will cause misclassification.
