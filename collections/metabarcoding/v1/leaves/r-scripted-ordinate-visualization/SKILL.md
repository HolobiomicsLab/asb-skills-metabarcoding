# r-scripted-ordinate-visualization

## Summary

A scripted R workflow that converts per-dataset, per-tool binary feature-call sets (e.g. significant ASVs from 14 differential abundance tools) into pairwise Jaccard distances, averages them across the 38 datasets, and visualizes tool clustering via PCoA ordination using parallelDist, vegan, and ggplot2.

## When to use

Use when you need to visualize how similar or clustered several methods' binary feature-call sets (e.g. significant ASVs) are, by ordinating pairwise Jaccard distances across replicate datasets.

## When NOT to use

- When the goal is to identify which taxa are significantly differentially abundant in a single dataset rather than to compare agreement between methods' call sets
- When evaluating false positive rates of tools via randomized groupings — that requires the run_all_FP_datasets_filt.sh / run_all_FP_datasets_unfilt.sh analysis, not cross-tool Jaccard ordination
- When comparing consistency of significant genera across different datasets from the same environment (e.g. the five diarrhea or five obesity datasets), which is a separate cross-study consistency analysis

## Inputs

- Per-dataset, per-tool significant ASV result tables produced by run_all_tools.sh (e.g. Expected_MALL_output-style outputs) for 38 filtered and 38 unfiltered 16S rRNA datasets
- ASV count tables (ASV_TABLE.tsv) and two-column metadata TSV files (sample IDs + sample groupings, max 2 groups)
- Mapfiles from Misc_datafiles for converting between working and clean study/tool names

## Outputs

- consensus_asv_tool_counts.tsv — a tool-tally table counting how many of the 14 tools called each ASV significantly DA, split by filtered/unfiltered runs
- fig3_pcoa_tool_jaccard.png — a ggplot2 PCoA ordination of tools based on mean pairwise Jaccard distances of their significant-ASV sets
- A mean Jaccard distance matrix (14x14, tools x tools) averaged over the 38 datasets

## How to apply

Load the per-dataset, per-tool significant-ASV result tables generated by run_all_tools.sh (from run_0.1_filt_datasets.sh on the 38 filtered datasets and run_no_filt_datasets.sh on the 38 unfiltered datasets). Pool significant ASV calls per tool and tally how many of the 14 tools called each ASV significantly DA, separately for filtered (10% prevalence filter, -F 0.1) and unfiltered runs. For each dataset, compute the pairwise Jaccard distance between every tool pair using the parallelDist package (0.2.4) with binary distance, then average the distance matrices across the 38 datasets. Run principal coordinates analysis on the mean Jaccard distance matrix using the vegan package (2.5.6) in R 3.6.3, then plot the ordination with ggplot2 (3.3.0), labeling tools by clustering behavior (e.g. the edgeR/LEfSe grouping). Judge correctness by checking that the tool-tally summary reproduces the reported pattern — filtering increases cross-tool agreement (mean 38.6% of significant ASVs called by more than 12 tools when filtered vs. 17.3% unfiltered) and that the ordination recovers known tool groupings.

## Examples

```
d <- parallelDist(t(sig_asv_matrix), method = "binary"); ord <- vegan::wcmdscale(d, k = 2); ggplot(as.data.frame(ord), aes(x = Dim1, y = Dim2, label = tool)) + geom_text()
```

## Evaluation signals

- The filtered-data tool-tally summary shows a higher proportion of ASVs called by more than 12 tools (reported mean 38.6%, SD 15.8%) than the unfiltered summary (mean 17.3%, SD 22.1%), confirming that prevalence filtering increases cross-tool agreement
- The distance matrix is 14x14 (one row/column per DA tool) with zero diagonal and Jaccard distances bounded in [0, 1]
- The PCoA ordination visually recovers known tool clustering behavior (e.g. edgeR/LEfSe grouping) as in the manuscript's Fig. 3
- Each tool's significant-ASV set is derived from output tables of run_all_tools.sh run consistently with -F 0.1 (filtered) or no filter flags across all 38 datasets
- Ordination run under R 3.6.3 with the pinned package versions from the README (vegan 2.5.6, parallelDist 0.2.4, ggplot2 3.3.0)

## Limitations

- The randomized approach for estimating FDR is not a perfect representation of real data, so agreement between tools does not guarantee correctness — 'there is no assurance that the intersection of the tool outputs is more reliable; it is possible that the tools are simply picking up the same noise as significant'
- Tool clustering behavior depends on data pre-processing; results differ between filtered (10% prevalence) and unfiltered runs, so the ordination must be reported per pre-processing regime
- Not all environments/datasets are appropriate for cross-study consistency comparison, so cross-tool agreement patterns may not generalize to a new environment
